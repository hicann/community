## 2. 测试目的与范围

- **目的**：以 cannbench 线上真实评测数据，端到端验证工作流（需求分析 → 方案设计 → 编码 → 测试工程 → 联调验收 → 提交）批量产出算子的质量与稳定性。
- **范围**：聚合方案全部 53 个算子（L1~L4），公开集 20 例/算子（共 1060 例）+ 隐藏集 80 例/算子（当前 51/53 算子已完成隐藏集评测，共 4080 例）。
- **不包含**：本地 pytest 功能/白盒用例结果（属工作流内部质量门禁，另有记录）。

## 3. 测试对象与产出规模

工作流为多角色协作流程（PM / architect / developer-code / developer-test / developer-doc / QA），含 7 个开发阶段与 CP0~CP5 六个检查点，产出经本地精度比对与性能验收后提交线上。

产出规模（截至数据抓取时点）：

- **53 个算子**（L1~L4），全部由本工作流生成；
- 当前最佳成绩共涉及 **95 个评测 job**（提交 → 评测 → 回归优化的多轮迭代）。

## 6. 观察与改进方向

- 隐藏集功能正确率（93.04%）低于公开集（98.68%）5.6 个百分点，反映本地测试用例对线上隐藏分布的边界覆盖仍有加强空间；
- 2 个算子尚未完成隐藏集评测，补齐后隐藏集得分仍有上升空间；
- 加速比处于 0.5~1.0 区间的算子约占四成，是后续性能迭代的主要增益区间。

## 7. 结论

以 cannbench official-tasks（Ascend950PR）线上评测为测试基准，直调算子开发工作流批量产出 53 个算子的聚合方案：

1. **工程稳定性达标**：编译通过率 100%，零反作弊违规，全部 5140 个用例综合通过率 94.20%；
2. **性能产出过半超基线**：隐藏集加速比中位数 1.19、平均 1.41，最高 8.16×；
3. **持续改进有效**：两日内总分提升 +322.45，验证了工作流「提交 → 评测 → 回归优化」闭环的迭代能力。

工作流满足批量高质量产出直调算子的设计目标。
